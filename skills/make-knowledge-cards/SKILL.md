# Make Knowledge Cards

把一段学习文本提炼成 5~8 张结构化知识卡，用于复习、记忆和自测。这是文本驱动型 Skill，由 AI 直接完成阅读、筛选、去重和组卡，不依赖额外脚本。

## 核心工作流

### 1. 读取输入

- 用户可能直接粘贴章节文本，也可能给出本地 `.md` / `.txt` 文件路径。
- 若给出文件路径，先用 `Read` 读取全文，再基于实际内容处理。
- 输入可能很长或包含多层标题，先通读全文再动手，不要只看开头就组卡。

### 2. 识别真正的知识点

- 通读全文，找出原文真正在讲什么：核心概念、机制、流程、结论、对比、规律。
- 忽略客套话、铺垫、重复的过渡句和与主题无关的例证。
- 每个知识点都必须能在原文中找到依据，不得加入原文没有的信息（不补充、不联想、不臆造）。

### 3. 去重与合并

- 同一知识点若在原文多处出现，只保留一次，删除重复表达。
- 相似或从属的知识点判断是否可合并为一张卡；合并后一张卡仍只讲一个主题。
- 若两个知识点被合并，卡片内容须只覆盖合并后那一件事，不要塞进两个主题。

### 4. 组卡（一张卡只讲一个知识点）

- 目标 5~8 张卡。数量由原文信息量决定，不是固定配额。
- 每张卡严格聚焦一个知识点，禁止把多个概念硬塞进一张卡。
- 信息不足（原文太短、太泛、只有几句话）时，**不要强行凑到 5 张**，如实给出少而准的卡片，并在结果末尾注明“原文信息有限，仅提炼出 N 张”。
- 若原文几乎没有任何可提炼的知识点（如只有问候语、空话、纯客套），则不输出卡片，直接说明“原文无法提炼出知识卡”，不要硬造一张。
- 信息极多时可精简合并，优先保留对读者最有价值的知识点，宁缺毋滥。

### 5. 输出卡片

按下面的固定结构，用 Markdown 输出每张卡：

```
### 卡片 N：<标题>

- **核心知识**：一句话讲清这个知识点是什么（须来自原文）。
- **简明解释**：用通俗语言展开说明原理或要点，3~5 句。
- **例子或自测问题**：给出一个源自原文的例子，或一个检验是否理解的自测问题（二选一即可）。
```

约束：

- 标题简短、能概括该卡的知识点。
- “核心知识”必须是原文中明确存在的陈述，不得改写引申出原文没有的观点。
- “例子”优先用原文自带的例子；原文没有例子时才用“自测问题”，且自测问题只针对原文讲到的内容。
- 卡片之间不要重复。
- 全文使用与原文一致的语言输出。

## 输出格式与交付

- 默认在对话中直接输出 Markdown 卡片列表（如上），卡片总数标注在开头，例如“共 5 张卡”。
- 若用户要求保存为文件，输出为一个 `.md` 文件并放入用户当前项目目录，文件名语义化（如 `knowledge-cards.md`），随后用 `present_files` 交付。
- 每张卡之间用空行分隔，保持结构清晰。

## 不支持的范围

遇到以下情况，明确告知用户本 Skill 不支持，并停止（不要硬转）：

- **网页抓取**：不接受网址去抓网页正文。
- **PDF**：不接受 PDF 文件。
- **Anki**：不导出 Anki 卡片格式。
- **图形界面**：不生成网页、卡片图或可视化界面，只产出 Markdown 文本卡片。

## 质量自检（每次输出前核对）

1. 卡片数量在 5~8 之间（原文信息不足时可少于 5，需说明）。
2. 每张卡只讲一个知识点。
3. 全部卡片内容都能在原文中找到依据。
4. 无重复卡片、无重复知识点。
5. 无原文没有的信息。
